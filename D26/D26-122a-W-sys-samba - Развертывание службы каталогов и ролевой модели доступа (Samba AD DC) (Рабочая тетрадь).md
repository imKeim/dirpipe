## Вводная

Сейчас ваша инфраструктура — это лоскутное одеяло из локальных учетных записей. Пять серверов — пять разных паролей. ## Раздел 2. Калибровка ядра и населения домена (5 баллов)

### Этап 2.1. Конфигурируем локальный резолвер и учетные записи (5 баллов)

> ℹ️ **Контекст**
>
> Контроллер домена поднят, но его сетевая карта всё ещё «смотрит» наружу. Контроллер обязан использовать **сам себя** (`127.0.0.1`) в качестве DNS-сервера, иначе он не сможет разрешать собственные SRV-записи и выдавать билеты Kerberos. 
> 
> После замыкания сети мы проведем «стресс-тест» инфраструктуры: запросим билет безопасности TGT у локального KDC, а затем сгенерируем структуру пользователей (`hquserX`) с помощью bash-цикла.

---

> ✅ **Задача**

> - [ ] **Инициировать** сессию Kerberos, получив билет администратора.
> - [ ] **Сформировать** базу пользователей контроллера через скрипт `samba-tool`.

---

> 💻 **В терминале сервера `BR-SRV`:**
>
> > 📥 **Замкните** внутренний DNS на Localhost.
> >
> > Сервер обязан обращаться за разрешением имен к самому себе (во встроенный DNS-движок Samba). Мы принудительно прописываем адрес локальной петли и доменный суффикс в конфигурацию сетевого адаптера.
> >
> > > ⌨️ **Впишите** точное имя вашей физической сетевой карты (например, `enp7s1` или `ens19`) вместо пропуска `___`. Узнать его можно командой `ip -br link`.

> > ```bash
> > echo "nameserver 127.0.0.1" > /etc/net/ifaces/___/resolv.conf
> > echo "search au-team.irpo" >> /etc/net/ifaces/___/resolv.conf
> > systemctl restart network
> > ```
>
> > 📥 **Протестируйте** связность DNS и запросите билет безопасности.
> >
> > Сначала мы убеждаемся, что внутренний DNS Samba «узнает» собственный домен. Затем запрашиваем билет администратора у службы `Kerberos` (KDC). Учтите, что регистр (большие буквы) в имени домена при вызове `kinit` критически важен.
> >
> > > ⌨️ **Впишите** пароль `P@ssw0rd`, когда терминал запросит авторизацию `Password for...` (текст не будет отображаться на экране).
> >
> > ```bash
> > host -t A au-team.irpo
> > kinit administrator@AU-TEAM.IRPO
> > ```
>
> > 📥 **Убедитесь**, что центр безопасности (KDC) выдал вам криптографический пропуск.
> >
> > ```bash
> > klist
> > ```
> >
> > 📤 **Ожидаемый вывод:** 
> > Вы должны увидеть таблицу билетов, где первой строкой значится `Default principal: administrator@AU-TEAM.IRPO`. Если её нет, значит пароль на предыдущем шаге введен неверно.
>
> > 📥 **Сгенерируйте** группы и аккаунты сотрудников.
> >
> > Bash-цикл мгновенно создаст 5 учетных записей, задаст им пароль `P@ssw0rd` и отключит срок действия пароля (требование удобства на экзамене), после чего добавит их в общую доменную группу `hq`.
> > ```bash
> > samba-tool group add hq
> >
> > for i in {1..5}; do
> >   samba-tool user add hquser$i P@ssw0rd
> >   samba-tool user setexpiry hquser$i --noexpiry

> > done
> >
> > samba-tool group listmembers hq
> > ```

## Раздел 3. Интеграция рабочих станций (RBAC) (5 баллов)

### Этап 3.1. Ввод в домен и настройка политик (5 баллов)

> ℹ️ **Контекст**
>
> Мы переходим на клиентскую машину `HQ-CLI`. Она управляется через `NetworkManager`, который может перезаписать наши настройки DNS, если получит старую информацию от DHCP. Поэтому мы принудительно укажем ему использовать контроллер домена.
>
> Как только машина «увидит» домен, мы введем её туда специальной утилитой `system-auth` (это специфика механики ОС ALT Linux, заменяющая долгие прокликивания в GUI). Наконец, мы реализуем **Ролевую модель (RBAC)**: привяжем доменную группу `hq` к локальной роли `wheel` и ограничим им права в `sudo`, как того требует задание. Пакеты для этого мы предусмотрительно скачали в прошлой работе.

> ✅ **Задача**
>
> - [ ] **Идентифицировать** имя сетевого соединения утилитой `nmcli`.
> - [ ] **Переопределить** DNS-сервер и применить параметры, чтобы клиент «увидел» `au-team.irpo`.
> - [ ] **Подключить** машину к Active Directory, используя учетную запись `administrator`.
> - [ ] **Включить** механизм `libnss-role` и связать доменную группу с локальной ролью.
> - [ ] **Сконфигурировать** файл ограничений `sudoers`, разрешив только 3 команды.
> - [ ] **Верифицировать** безопасность, выполнив тестовый вход под доменным пользователем.

---

> 🤔 **Мысли**
> 
> 🔭 **Визионер пророчествует:**
> Сейчас мы совершим «цифровой обряд»: машина `HQ-CLI` перестанет быть гордым одиночкой и станет частью империи `au-team.irpo`. 
> 
> В этот момент локальная база пользователей `/etc/passwd` на клиенте отходит на второй план. С этого момента клиент будет «звонить» на сервер `BR-SRV` при каждой попытке входа, чтобы спросить: «А есть ли такой человек и какой у него пароль?». Мы меняем **Локальное доверие** на **Централизованную власть**. Это фундамент масштабируемости: завтра вы сможете добавить 1000 таких машин, и вам не придется создавать на каждой из них пользователей вручную.

---

> 💻 **На клиенте `HQ-CLI`:**
>
> > 📥 **Узнайте** имя вашего профиля конфигурации.
> > 
> > Утилита `nmcli` работает не с «железом» (порт `DEVICE`), а с логическими профилями сети. Выполните команду ниже и скопируйте значение строго из первого столбца — `NAME` (например, `System enp7s1` или `DHCP-CLI`). Не перепутайте!
> > 
> > ```bash
> > nmcli c show --active
> > ```
> 
> > 📥 **Зафиксируйте** DNS и введите ПК в домен.
> > 
> > > ⌨️ **Впишите** скопированное имя из столбца NAME вместо `___` (например, `DHCP-CLI`). Обязательно сохраните кавычки, так как в именах профилей часто встречаются пробелы!
> > 
> > ```bash
> > nmcli con mod "___" ipv4.dns "192.168.3.10"
> > nmcli con mod "___" ipv4.ignore-auto-dns yes
> > nmcli con up "___"
> > 
> > system-auth write ad au-team.irpo hq-cli au-team administrator P@ssw0rd
> > 
> > systemctl restart sssd
> > sleep 3
> > ```
>
> > 📤 **Ожидаемый вывод:** 
> > Возможно предупреждение `No credentials cache found` — это безопасность утилиты, игнорируйте его. Ошибок быть не должно. Задержка в 3 секунды позволит системе загрузить группы из домена.
>
> > 📥 **Настройте** делегирование прав и ограничения.
> > 
> > Маппим `hq` с ролью `wheel` и запрещаем им делать всё, кроме 3-х базовых команд.
> > ```bash
> > control libnss-role enabled
> > roleadd hq wheel
> > 
> > cat <<EOF > /etc/sudoers.d/hq_restrictions
> > Cmnd_Alias HQ_CMDS = /bin/cat, /bin/grep, /usr/bin/id
> > %wheel ALL=(ALL) NOPASSWD: HQ_CMDS
> > EOF
> > ```
>
> > 📥 **Подготовьте** профиль и смените пользователя.
> >
> > Если бы вы сейчас зашли в систему «честно» (через графический экран входа), умный PAM-модуль сам бы создал папку для нового доменного пользователя. Но мы используем команду быстрого переключения терминала (`su -`). Чтобы система не ругалась на отсутствие дома (`No directory`), мы собираем профиль пользователя вручную, копируя в него эталонные системные настройки из `/etc/skel`.
> > 
> > Мы используем обратный слэш `\` перед командой `cp`, чтобы подавить любые навязчивые вопросы оболочки о перезаписи файлов.
> >
> > Команда `su -` переключит терминал в сессию доменного юзера `hquser1`.
> > 
> > > ⚠️ **Внимание:** Смена контекста
> > > 
> > > После этой команды вы перестанете быть `root`’ом. Оболочка изменится, и скопировать оставшийся скрипт целиком уже не получится. Вводите оставшиеся команды строго **по одной строке**!
> 
> > ```bash
> > mkdir -p /home/AU-TEAM.IRPO/hquser1
> > \cp -af /etc/skel/. /home/AU-TEAM.IRPO/hquser1/
> > chown -R hquser1:hq /home/AU-TEAM.IRPO/hquser1
> >
> > su - hquser1
> > ```
> > 
> > 📥 **Проверьте** доступность разрешенных команд.
> > 
> > Обратите внимание: приглашение терминала изменилось на `hquser1`. Введите команду проверки прав (может потребоваться ввести доменный пароль `P@ssw0rd`).
> > ```bash
> > sudo id
> > ```
> 
> > 📥 **Атакуйте** собственные настройки (Стресс-тест).
> >
> > Сымитируйте деструктивное действие. Введите команду вручную или подтвердите вставку из буфера (оболочка Bash часто блокирует случайную вставку опасных команд вроде `reboot`). Система должна жёстко пресечь попытку.
> > ```bash
> > sudo reboot
> > ```
>
> > 📤 **Ожидаемый вывод:**
> > Вы успешно зайдете под пользователем (появится привычное приглашение `[hquser1@hq-cli ~]$`). Команда `id` выполнится успешно (вы увидите UID `hquser1`), а `reboot` вернет жёсткий отказ: `Sorry, user hquser1 is not allowed to execute '/sbin/reboot'`. То, что нужно.
>
> > 📥 **Покиньте** ограниченную оболочку.
> >
> > Вернитесь в сессию суперпользователя `root` для продолжения работы на сервере.
> > ```bash
> > exit
> > ```

> 🩹 **Ремкомплект**
>
> **Проблема:** 
> Домен развернут, но пароль Администратора не подходит (ошибка авторизации на следующих этапах) или мастер `provision` завершился критической ошибкой.
>
> **Симптом:**
> Команды вроде `kinit administrator` или `system-auth` возвращают ошибку `Preauthentication failed` или `Logon is invalid`.
>
> **Причина:**
> При настройке `samba-tool` вы ввели пароль `P@ssw0rd` на русской раскладке клавиатуры (`З"ыыц0кв`) или с нажатым CapsLock. База данных LDAP сохранила неверный хэш.
> 
> Обычная переустановка пакета не поможет: Samba хранит бинарные базы отдельно. Чтобы пересоздать домен, необходимо физически уничтожить старую инфраструктуру каталогов.
>
> **Решение (Выжженная земля):**
> 
> > ❌ **Запрещено:** 
> > Выполнять данный скрипт, если ваша служба работает корректно и вы получили билет Kerberos. Команды ниже безвозвратно уничтожают контроллер домена (Active Directory). Используйте их **исключительно** для устранения ошибки неверного пароля.
>
> > 💻 **В терминале сервера `BR-SRV`:**
> > 
> > > 📥 **Остановите** службу, **удалите** конфиг и **сотрите** бинарные базы.
> > > ```bash
> > > systemctl stop samba
> > > rm -f /etc/samba/smb.conf
> > > rm -rf /var/lib/samba/*
> > > rm -rf /var/cache/samba/*
> > > ```
> > > После этого вернитесь в начало **Этапа 1.1** и запустите команду `samba-tool domain provision` заново, внимательно проверяя раскладку клавиатуры.
