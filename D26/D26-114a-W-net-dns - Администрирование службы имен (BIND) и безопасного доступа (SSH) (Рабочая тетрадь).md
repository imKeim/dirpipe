## Раздел 1. Развертывание службы имен (DNS)

### 1.1. Инициализируем авторитетный сервер BIND

> ℹ️ **Контекст**
>
> Человеческий мозг плохо запоминает цифры. Адрес `hq-srv` запомнить проще, чем `172.16.100.2`. Мы превратим сервер `HQ-SRV` в главный адресный справочник (Primary DNS) нашей организации.
>
> > ⚠️ **Обратите внимание:** 
В операционных системах семейства ALT Linux служба BIND работает в изолированном, защищенном контейнере (`chroot`). Это означает, что все конфигурационные файлы физически располагаются в директории `/var/lib/bind/etc`, но для удобства администратора в систему проброшены символические ссылки (symlinks) в привычный каталог `/etc/bind`. Мы будем работать именно через них.

---

> ✅ **Задача (3 балла)**
>
> - [ ] **Сконфигурировать** маршрутизацию пакетного менеджера на кэш-сервер колледжа для ускорения загрузки (так как сервер `HQ-SRV` выходит в Интернет впервые).
> - [ ] **Установить** пакеты службы BIND и утилиты сетевой диагностики.
> - [ ] **Создать** криптографический ключ управления демоном (`rndc`).
> - [ ] **Зафиксировать** глобальные параметры DNS-сервера (разрешение рекурсии и пересылку неизвестных запросов внешним провайдерам).

---

> 💻 **В терминале сервера `HQ-SRV`:**
>
> > 📥 **Ускорьте** загрузку и **установите** ПО.
> >
> > Команда `sed` перехватит обращения к медленным серверам ALT Linux и перенаправит их на локальный кэш `10.45.33.250`. Установка пройдет мгновенно.
> >
> > ```bash
> > sed -i 's|http://ftp.altlinux.org/pub/distributions/ALTLinux|http://10.45.33.250:3142/altlinux|g' /etc/apt/sources.list.d/alt.list
> > apt-get update && apt-get install -y bind bind-utils
> > ```
>
> > 📥 **Сгенерируйте** ключ управления и **подготовьте** хранилище зон.
> >
> > ```bash
> > rndc-confgen -a -c /etc/bind/rndc.key
> > mkdir -p /etc/bind/zone
> > ```
>
> > 📥 **Настройте** глобальные параметры BIND.
> >
> > Файл `options.conf` определяет базовое поведение ядра службы. Каждая директива решает конкретную задачу:
> > *   `recursion yes;` — Разрешает серверу самому искать ответы в глобальном Интернете, если он не нашел их в своей локальной базе.
> > *   `allow-query { any; };` — Разрешает любым компьютерам сети задавать нашему серверу вопросы.
> > *   `forwarders { 8.8.8.8; 77.88.8.8; };` — Назначает публичные серверы Google и Яндекс в качестве «вышестоящих помощников» для пересылки неизвестных запросов.
> > *   `dnssec-validation no;` — Отключает криптографическую проверку подлинности ответов (для упрощения учебной среды).
> >
> > ```bash
> > cat <<EOF > /etc/bind/options.conf
> > options {
> >     recursion yes;
> >     allow-query { any; };
> >     forwarders { 8.8.8.8; 77.88.8.8; };
> >
> >     dnssec-validation no;
> >     listen-on-v6 { none; };
> > };
> > EOF
> > ```

### 1.2. Конфигурируем прямую и обратную зоны

> ℹ️ **Контекст**
>
> Мы создаем «Паспортный стол» сети. Прямая зона (`au-team.irpo`) переводит человекочитаемые имена в IP-адреса. Обратная зона (`16.172.in-addr.arpa`) делает наоборот — переводит IP-адреса в имена, что критически важно для работы систем антиспама и лог-анализаторов.

---

> ✅ **Задача (3 балла)**
>
> - [ ] **Объявить** прямую и обратную зоны в конфигурационном файле `local.conf`.
> - [ ] **Сгенерировать** файлы зон, наполнив их ресурсными записями `A`, `PTR`, `NS` и `SOA` строго в соответствии со Справочной таблицей в начале тетради.
> - [ ] **Передать** права владения на созданные файлы системному пользователю `named`.
> - [ ] **Запустить** демона BIND и верифицировать отсутствие синтаксических ошибок.

---

> 💻 **В терминале сервера `HQ-SRV`:**
>
> > 📥 **Объявите** зоны в главном реестре.
> >
> > ```bash
> > cat <<EOF > /etc/bind/local.conf
> > zone "au-team.irpo" {
> >     type master;
> >     file "/etc/bind/zone/au-team.irpo";
> > };
> >
> > zone "16.172.in-addr.arpa" {
> >     type master;
> >     file "/etc/bind/zone/16.172.in-addr.arpa";
> > };
> > EOF
> > ```
>
> > 📥 **Создайте** файл **прямой зоны** (Forward Zone).
> >
> > Этот файл переводит человекочитаемые доменные имена (FQDN) в IP-адреса с помощью записей типа `A` (Address Record):
> > *   **Синтаксис имен:** Если слева указано короткое имя (например, `hq-rtr`), сервер автоматически допишет к нему ваш домен (`.au-team.irpo`).
> > *   **Закон точки:** Обратите внимание на точки (`.`) в конце полных доменных имен (например, `root.au-team.irpo.`). Точка обозначает «Корень Интернета» (абсолютное имя). Если вы забудете поставить точку в конце, BIND посчитает имя относительным и ошибочно приклеит к нему ваш домен еще раз (получится `root.au-team.irpo.au-team.irpo`), что приведет к фатальному сбою разрешения имен.
> >
> > ```bash
> > cat <<EOF > /etc/bind/zone/au-team.irpo
> > \$TTL    604800
> > @       IN      SOA     hq-srv.au-team.irpo. root.au-team.irpo. (
> >                               1         ; Serial
> >                          604800         ; Refresh
> >                           86400         ; Retry
> >                         2419200         ; Expire
> >                          604800 )       ; Negative Cache TTL
> > ;
> > @       IN      NS      hq-srv.au-team.irpo.
> > @       IN      A       172.16.100.2
> > ;
> > hq-srv  IN      A       172.16.100.2
> > hq-rtr  IN      A       172.16.100.1
> > hq-cli  IN      A       172.16.200.10
> > br-rtr  IN      A       172.16.2.2
> > br-srv  IN      A       172.16.10.2
> > docker  IN      A       172.16.1.1
> > web     IN      A       172.16.2.1
> > EOF
> > ```
>
> > 📥 **Создайте** файл **обратной зоны** (Reverse Zone).
> >
> > Обратная зона делает наоборот — переводит известные IP-адреса обратно в имена хостов с помощью записей типа `PTR` (Pointer Record):
> > *   **Синтаксис сети:** Имя самой зоны (`16.172.in-addr.arpa`) читается как сеть `172.16.0.0/16`, записанная задом наперед. Это международный стандарт архитектуры DNS.
> > *   **Запись хостов:** В левой колонке мы указываем только недостающие октеты (цифры) конкретного IP-адреса (в обратном порядке), так как первые два октета уже зашифрованы в названии зоны. Например, цифры `2.100` ядро сложит с названием зоны и превратит в адрес `172.16.100.2`.
> >
> > ```bash
> > cat <<EOF > /etc/bind/zone/16.172.in-addr.arpa
> > \$TTL    604800
> > @       IN      SOA     hq-srv.au-team.irpo. root.au-team.irpo. (
> >                               1         ; Serial
> >                          604800         ; Refresh
> >                           86400         ; Retry
> >                         2419200         ; Expire
> >                          604800 )       ; Negative Cache TTL
> > ;
> > @       IN      NS      hq-srv.au-team.irpo.
> > ;
> > 2.100   IN      PTR     hq-srv.au-team.irpo.
> > 1.100   IN      PTR     hq-rtr.au-team.irpo.
> > 10.200  IN      PTR     hq-cli.au-team.irpo.
> > EOF
> > ```
>
> > 📥 **Исправьте** права доступа и запустите службу.
> >
> > Вы создали файлы от имени пользователя `root`. Служба работает от имени бесправного пользователя `named`. Если не передать права (`chown`), BIND не сможет прочитать зоны и вернет ошибку.
> >
> > ```bash
> > chown root:named /etc/bind/zone/*
> > chmod 640 /etc/bind/zone/*
> >
> > systemctl enable --now bind
> > systemctl status bind --no-pager
> > ```
>
> > 📤 **Ожидаемый вывод:**
> > Вы должны увидеть зеленый индикатор `Active: active (running)`.
> >
> > > 💡 **Примечание:** Если в логах службы вы видите предупреждение `the working directory is not writable` — **это нормально**. Мы выдали демону права только на чтение файлов (Read-Only) ради безопасности. Главное — убедитесь в наличии строк `loaded serial 1` для обеих зон и финальной надписи `all zones loaded`.
> >
> > ```text
> > Active: active (running) since ...
> > ...
> > zone 16.172.in-addr.arpa/IN: loaded serial 1
> > zone au-team.irpo/IN: loaded serial 1
> > all zones loaded
> > running
> > ```

---

> 🩹 **Ремкомплект**  
> 
> **Проблема:** 
> Служба `bind` не запускается (красный статус `failed`).
>
> **Симптом:**
> Демон падает при старте. В логах (вызов `journalctl -u bind -e`) видны ошибки вида `unexpected token` или `file not found`.
>
> **Причина:**
> Вы допустили синтаксическую ошибку. BIND — самый капризный сервис в Linux. Лишняя точка запятой (`;`), забытая скобка `}` или опечатка в пути к файлу (`au-tame.irpo`) убивают запуск.
>
> **Решение (Встроенный линтер):**
> У BIND есть утилиты-аудиторы, которые точно покажут строку с ошибкой.
> > 💻 **В терминале сервера `HQ-SRV`:**
> > > 📥 **Проверьте** глобальный конфиг на опечатки:
> > > ```bash
> > > named-checkconf /etc/bind/named.conf
> > > ```
> > 
> > > 📥 **Проверьте** синтаксис конкретной зоны (ищите `OK`):
> > > ```bash
> > > named-checkzone au-team.irpo /etc/bind/zone/au-team.irpo
> > > ```
> > Исправьте найденную утилитой ошибку через редактор `nano` и выполните `systemctl restart bind`.
