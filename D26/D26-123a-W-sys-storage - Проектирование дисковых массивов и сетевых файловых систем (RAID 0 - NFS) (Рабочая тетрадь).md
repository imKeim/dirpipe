> - 📝 **Описание:** Практикум направлен на **формирование навыков** управления физической дисковой подсистемой Linux (`mdadm`), организации высокопроизводительных массивов (RAID 0) и развертывания системы централизованного хранения данных по протоколу Network File System (NFS).

## Вводная

Инфраструктура — это не только каналы связи и учетные записи Active Directory. Это, прежде всего, **Данные**. Инженер может построить идеальную сеть, но если пользователям негде хранить документы, система мертва. Наша задача — превратить сервер `HQ-SRV` в главный файловый архив компании.

Для этого мы применим многоуровневый подход. На физическом уровне мы скомбинируем два пустых диска в единый массив **RAID 0 (Stripe)**. Эта архитектура разбивает файлы на куски и пишет их на два диска параллельно. Это удваивает скорость и суммирует объем, но (внимание!) это чистый Trade-off: отказ любого из двух дисков приведет к потере 100% данных всего массива. Поверх этой быстрой, но хрупкой блочной структуры мы развернем надежную файловую систему и транслируем её в сеть по протоколу **NFS**, ограничив доступ периметром нашей клиентской сети.

## Раздел 1. Дисковая подсистема: Software RAID (3 балла)

> 📍 **Контрольная точка**
>
> Прежде чем форматировать диски, необходимо ознакомиться с официальным заданием.
> - [ ] **Прочитайте** в «Полном списке заданий» (Модуль 2) требования к настройке **файлового хранилища (RAID)** и сервера **сетевой файловой системы (NFS)**.

### 1.1. Развертываем блочное хранилище (3 балла)

> ℹ️ **Контекст**
>
> В сервере `HQ-SRV` аппаратно установлены два дополнительных диска (`/dev/sdb` и `/dev/sdc`). Сейчас это «сырое» железо. 
> Мы создадим «Матрешку архитектора»: 
> 1.  С помощью утилиты `mdadm` мы склеим оба диска в одно логическое блочное устройство (`md0`).
> 2.  Сохраним метаданные (`UUID`) сборки в ядро, чтобы массив не «рассыпался» после перезагрузки.
> 3.  Отформатируем логическое устройство в файловую систему `ext4`.
> 4.  Впишем «закон монтирования» в системную конституцию (`fstab`), чтобы папка `/raid` оживала при каждом старте системы.

---

> ✅ **Задача**
>
> - [ ] **Установить** утилиту управления массивами `mdadm`.
> - [ ] **Сгенерировать** массив RAID уровня 0 из двух физических дисков и зафиксировать его конфигурацию (`tee -a`).
> - [ ] **Форматировать** блочное устройство в ФС `ext4`.
> - [ ] **Организовать** автоматическое монтирование устройства в системный каталог `/raid` через файл `fstab`.

---

> 💻 **На сервере `HQ-SRV`:**
> 
> > 📥 **Установите** утилиту и соберите физический массив.
> > 
> > Команда `--run` заставит `mdadm` собрать массив без лишних вопросов (даже если диски ранее использовались).
> >
> > ```bash
> > apt-get update && apt-get install -y mdadm
> > 
> > mdadm --create /dev/md0 --level=0 --raid-devices=2 /dev/sdb /dev/sdc --run
> > cat /proc/mdstat
> > ```
>
> > 📤 **Ожидаемый вывод:** 
> > В статусе ядра должно быть указано `md0 : active raid0 sdc... sdb...`.
> 
> > 📥 **Зафиксируйте** метаданные и отформатируйте диск.
> > 
> > Сохраняем «паспорт» массива (UUID) в системный конфиг и создаем файловую систему `ext4`.
> >
> > ```bash
> > mdadm --detail --scan | tee -a /etc/mdadm.conf
> > mkfs.ext4 /dev/md0
> > ```
>
> > 📤 **Ожидаемый вывод:** 
> > Сообщение о создании суперблоков и таблиц файловой системы (`Writing superblocks... done`).
>
> > 📥 **Настройте** автоматическое монтирование.
> > 
> > Вписываем массив в `fstab`, создаем папку и монтируем.
> >
> > ```bash
> > mkdir -p /raid
> > echo "/dev/md0 /raid ext4 defaults 0 0" >> /etc/fstab
> > mount -a
> > df -h | grep /raid
> > ```
>
> > 📤 **Ожидаемый вывод:** 
> > Вы должны увидеть строку с диском `/dev/md0` размером около `2.0G`, смонтированным в папку `/raid`.

> 🤔 **Мысли**
>
> 🪘 **Шаман объясняет природу вещей:**
> Вы создали RAID 0. Для операционной системы это просто диск `/dev/md0`. Но на физическом уровне происходит магия «расслоения реальности». Файл, который вы сохраняете, рубится на тысячи мелких кусочков (chunks), и контроллер швыряет их одновременно на два диска, как ди-джей на два винила. Именно эта параллельная запись и дает удвоение скорости. Вы обманули физику, заставив два медленных диска работать как один быстрый.

## Раздел 2. Открытие сетевого доступа (NFS) (3 балла)

### 2.1. Конфигурируем NFS-сервер (3 балла)

> ℹ️ **Контекст**
>
> Теперь, когда `HQ-SRV` обладает мощным локальным диском `/raid`, мы превращаем его в сетевую шару по протоколу NFS (Network File System).
> Обратите внимание, мы не расшариваем диск «для всех». В файле `/etc/exports` будет жестко вшито правило: доступ имеет право получить только сеть клиентов (`192.168.2.0/28`). Пакеты из других сетей будут отброшены самим демоном NFS.

> - [ ] **Активировать** службу и принудительно обновить таблицу кэша разрешений (`exportfs`).

---

> 💻 **В терминале сервера `HQ-SRV`:**
> 
> > 📥 **Установите** службы и подготовьте целевую папку.
> > 
> > Мы выдаем полные права `777`, чтобы не столкнуться с ошибками доступа при тестировании из клиентского терминала.
> >
> > ```bash
> > apt-get update && apt-get install -y nfs-server nfs-utils
> > mkdir -p /raid/nfs
> > chmod 777 /raid/nfs
> > ```
>
> > 📥 **Сконфигурируйте** права сетевого доступа.
> > 
> > Флаг `no_root_squash` опасен в продакшене, но здесь он позволит `root`’у клиента беспрепятственно писать файлы на наш сервер.
> >
> > ```bash
> > echo "/raid/nfs 192.168.2.0/28(rw,sync,no_root_squash,no_subtree_check)" > /etc/exports
> > ```
>
> > 📥 **Активируйте** экспорт сетевых ресурсов.
> > 
> > Запускаем демона и принудительно заставляем его перечитать таблицу `exports`.
> >
> > ```bash
> > systemctl enable --now nfs-server
> > exportfs -arv
> > ```
>
> > 📤 **Ожидаемый вывод:** 
> > Система должна отрапортовать `exporting 192.168.2.0/28:/raid/nfs`.
