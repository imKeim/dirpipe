## Вводная

На данном этапе ваш маршрутизатор **HQ-RTR** напоминает голову без тела. У него есть связь с внешним миром, но внутренняя инфраструктура главного офиса мертва. Серверы и клиенты физически скоммутированы через виртуальный коммутатор, но логически изолированы в вакууме: они не имеют IP-адресов, не видят маршрутизатор и не подозревают о существовании друг друга.

Ваша задача — превратить этот хаос в структурированную и безопасную систему. Вы примените технологию **VLAN**, чтобы логически «разрезать» один физический кабель на изолированные сегменты (для серверов, пользователей и управления). После этого вы развернете службу **DHCP**, которая автоматизирует подключение новых клиентов, навсегда избавив администратора от рутинной настройки IP-адресов.

### 1.1. Тегируем аппаратные порты в гипервизоре (Только 🟢 Greenfield)

### 1.2. Конфигурируем подынтерфейсы (Router-on-a-Stick)

> ℹ️ **Контекст**
>
> В вашем маршрутизаторе `HQ-RTR` физически недостаточно сетевых карт, чтобы подключить серверы, пользователей и администраторов в разные порты. Мы используем технологию **Router-on-a-Stick**: берем один физический внутренний порт (Trunk) и программно «нарезаем» его на три виртуальных канала (VLAN), каждый со своим шлюзом.

---

> ✅ **Задача (5 баллов)**
>
> - [ ] **Создать** структуру конфигурационных директорий для трех изолированных L2-доменов.

> - [ ] **Зафиксировать** L3-адресацию шлюзов по умолчанию для каждой подсети согласно таблице целевой топологии **Модуля 2**.

---

> 💻 **В терминале маршрутизатора `HQ-RTR`:**
>
> > 📥 **Настройте** подсеть для серверов (SRV-Net).
> >
> > Файл `options` задает физику виртуального канала:
> > *   `TYPE=vlan` переводит драйвер в режим 802.1Q.
> > *   `HOST` указывает на реальный медный порт (несущую трубу).
> > *   `VID` — на номер вашей изолированной сети внутри этой трубы.
> >
> > > ⌨️ **Впишите** вместо `[Тег серверов]` ваш VLAN ID (возьмите его из 📋 **Матрицы идентификации** в начале рабочей тетради).
> >
> > > ⌨️ **Впишите** вместо `[Внутренний порт]` физическое имя порта роутера (например, `enp7s2` или `ens20`).
> >
> > ```bash
> > mkdir -p /etc/net/ifaces/vlan[Тег серверов]
> >
> > echo "TYPE=vlan" > /etc/net/ifaces/vlan[Тег серверов]/options
> > echo "HOST=[Внутренний порт]" >> /etc/net/ifaces/vlan[Тег серверов]/options
> > echo "VID=[Тег серверов]" >> /etc/net/ifaces/vlan[Тег серверов]/options
> >
> > echo "172.16.100.1/28" > /etc/net/ifaces/vlan[Тег серверов]/ipv4address
> > ```
>
> > 📥 **Настройте** подсеть для клиентов (CLI-Net).
> >
> > > ⌨️ **Впишите** вместо `[Тег клиентов]` ваш VLAN ID для клиентов (строго из вашей 📋 **Матрицы идентификации**).
> >
> > > ⌨️ **Впишите** вместо `[Внутренний порт]` то же самое физическое имя провода, что и в предыдущем шаге.
> >
> > ```bash
> > mkdir -p /etc/net/ifaces/vlan[Тег клиентов]
> >
> > echo "TYPE=vlan" > /etc/net/ifaces/vlan[Тег клиентов]/options
> > echo "HOST=[Внутренний порт]" >> /etc/net/ifaces/vlan[Тег клиентов]/options
> > echo "VID=[Тег клиентов]" >> /etc/net/ifaces/vlan[Тег клиентов]/options
> >
> > echo "172.16.200.1/27" > /etc/net/ifaces/vlan[Тег клиентов]/ipv4address
> > ```
>
> > 📥 **Настройте** подсеть управления (Management).
> >
> > > ⌨️ **Впишите** вместо `[Тег управления]` ваш VLAN ID для сети управления.

> > mkdir -p /etc/net/ifaces/vlan[Тег управления]
> >

### 1.3. Активируем магистральный физический порт (Trunk)

> ℹ️ **Контекст**
>
> Созданные нами папки `vlan` — это «души» сетей. Им нужно физическое тело. Если мы не поднимем базовый интерфейс (например, `enp7s2`), то ни один VLAN поверх него не заработает.
>
> Фундаментальное правило: **Магистральный порт (Trunk) не должен иметь собственного IP-адреса**. Его задача — быть «глупой трубой», пропускающей тегированные кадры. Мы принудительно очистим его от старых адресов и запустим сеть.

---

> ✅ **Задача (5 баллов)**
>
> - [ ] **Очистить** родительский физический интерфейс от L3-маршрутизации (IP-адресов).
> - [ ] **Инициировать** активацию порта как базовой несущей для VLAN-трафика.
> - [ ] **Перезапустить** сетевой стек маршрутизатора и верифицировать создание подынтерфейсов.

---

> 💻 **В терминале маршрутизатора `HQ-RTR`:**
>
> > 📥 **Очистите** и **поднимите** магистральный порт.
> >
> > > ⌨️ **Впишите** вместо `[Внутренний порт]` имя вашей физической сетевой карты (то же самое, что вы указывали в параметре `HOST=` выше).
> >
> > ```bash
> > mkdir -p /etc/net/ifaces/[Внутренний порт]
> > rm -f /etc/net/ifaces/[Внутренний порт]/ipv4address
> >
> > echo "TYPE=eth" > /etc/net/ifaces/[Внутренний порт]/options
> > ```
>
> > 📥 **Примените** конфигурацию и **проверьте** интерфейсы.
> >
> > ```bash
> > systemctl restart network && ip -c a
> > ```
>
> > 📤 **Ожидаемый вывод:**
> > Наличие символа `@` означает, что ядро успешно создало логическую привязку VLAN (802.1Q) к физическому кабелю. Убедитесь, что сам базовый порт `[Внутренний порт]` находится в состоянии `UP`, но **не имеет** строки `inet` (IP-адреса).
> > ```text
> > 3: [Внутренний порт]: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 ... state UP ...
> > ...
> > 4: vlan[Тег серверов]@[Внутренний порт]: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 ...
> >     inet 172.16.100.1/28 scope global vlan[Тег серверов]
> > 5: vlan[Тег клиентов]@[Внутренний порт]: ... inet 172.16.200.1/27 ...
> > 6: vlan[Тег управления]@[Внутренний порт]: ... inet 172.16.99.1/29 ...
> > ```

---

> 🩹 **Ремкомплект**  
> 
> **Проблема:**  
> Команда `systemctl restart network` выдает красную ошибку `Failed to start LSB: Bring up/down networking` или подынтерфейсы отсутствуют в `ip a`.
>
> **Симптом:**
> Служба сети аварийно завершила работу. Виртуальные локальные сети не созданы.
>

Для идентификации клиента мы используем не его аппаратный MAC-адрес (который генерируется гипервизором случайно и нам неизвестен), а специальный идентификатор **`dhcp-client-id`** (`01:11:11:11:11:11:11`).
>
> Стандартная служба `network` в ALT Linux очень плохо работает с подменой `client-id`. Поэтому здесь мы применяем **инверсию**: мы отключаем старую службу `network` и, наоборот, **включаем современный `NetworkManager`**. Его утилита `nmcli` позволяет одной строкой создать профиль подключения и передать нужный идентификатор нашему роутеру.

> 
> **Проблема:** 
> Команда `nmcli con up lan` зависает, а затем выдает ошибку тайм-аута (Timeout) или `IP configuration could not be reserved`.

> **Симптом:**
> Клиент отправляет в сеть широковещательные запросы `DHCP DISCOVER`, но сервер (`HQ-RTR`) ему не отвечает.

> **Причина (Изоляция L2):**
> Маршрутизатор слушает запросы строго внутри `vlan200`. Если ваш клиент не получил IP, значит его запросы вылетают из виртуальной машины **без тега** (Untagged) и отбрасываются коммутатором.

> **Решение (Настройка гипервизора):**
